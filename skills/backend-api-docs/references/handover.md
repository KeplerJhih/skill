# 交接 API 給其他開發者或 AI

目標：對方（原生 App、前端、外包，或他們手上的 AI 工具）拿到東西後不用再問你。

## 交付清單

| 交付物 | 內容 | 給誰 |
|---|---|---|
| `docs/openapi3.json` | 契約正本 | 所有人；型別產生器、MCP 產生器、AI 都吃這個 |
| 文件頁網址 | `/docs/`（非正式環境）；對方能連到時最好讀 | 人 |
| `llms.txt`（一頁索引） | 端點清單、認證方式、規格看不出來的業務慣例 | AI 為主，人也適合當導讀 |
| 測試帳號與登入端點 | 給文件頁的登入列用 | 人 |

不要交付的：Swagger UI 截圖、2.0 中間產物、手寫的端點表（會和規格漂移）。

## 為什麼要有 `llms.txt`

完整規格通常幾百 KB，整份丟進對話會吃掉大量 context，模型也容易被細節淹沒。一頁索引讓 AI 先掌握全貌與慣例，再按需要查規格。內容分三段：

```markdown
# <系統名稱> API

## 概觀
- 入口：後台 `/admin`（admin 角色）、客戶端 `/api`（customer 角色）；認證 Bearer JWT，登入端點 …
- 規格：openapi3.json（OpenAPI 3.0）；文件頁 /docs/
- 回應格式：{ code, message, data }；列表 data = { items, total, page, limit }
- 金額 / 匯率為字串且小數位不固定；日期 YYYY-MM-DD；PUT 為整包取代，null = 清除

## 端點索引（依 tag）
- Admin - Orders：訂單、品項、費用、附件 → GET/POST /admin/orders、…
- …

## 規格看不出來的規則
- 餘額只從交易紀錄累計，不存欄位
- 匯率三層覆寫：單項 → 訂單 → 全局
- 客戶端回應不含供應商、採購價、費用拆解
```

「端點索引」可從規格的 tag 與 summary 自動產（`make swagger` 一起跑）；「規則」段要人寫，從專案 CLAUDE.md 與架構文件的慣例抽。

## 什麼時候才做 MCP

MCP server 讓 AI **直接呼叫** API（查資料、重現問題），不只是讀文件。值得做的條件：

- 團隊真的在用 AI 開發或除錯，而且常需要「看實際資料」。
- 能給 AI 一把受限的鑰匙：專用帳號、端點白名單、只讀為主。
- 規格是 3.x（多數 OpenAPI → MCP 產生器只吃 3.x）。

沒有這些條件時，規格檔 + `llms.txt` 就夠了。文件頁工具（例如 Scalar）附的 MCP / Ask AI 多半是託管服務，會把規格上傳到第三方，預設關閉。
